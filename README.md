# ITD Studio

Сайт студии, кабинет клиента и административная панель. Требуется **Node.js 24.13 или новее в ветке 24 LTS** (используется встроенный `node:sqlite`). Сторонних зависимостей, установки npm-пакетов и сборки нет.

## Локальный запуск

В каталоге репозитория выполните `npm start`. Сервер слушает `127.0.0.1:8000`.

- `/` — главная страница;
- `/anketa` — существующая анкета;
- `/cabinet` — регистрация, вход, кабинет; после входа администратора здесь же появляется управление проектами.

`PORT` и `HOST` меняют адрес сервера. `ITD_DATA_DIR` задаёт постоянный каталог базы и документов; по умолчанию `/workspace/.itd-data`. Храните его вне публичных каталогов и не добавляйте в Git. Процессы нужно запускать заново после восстановления облачной среды.

## Создание администратора

При первом запуске передайте `ITD_ADMIN_EMAIL` и `ITD_ADMIN_PASSWORD`. Пароль — от 12 до 256 символов. Не записывайте настоящий пароль в исходники, команды с буквальным значением, переписку или сохранённые инструкции. Например, в интерактивном Bash:

```bash
read -rp 'Email администратора: ' ITD_ADMIN_EMAIL
read -rsp 'Новый пароль администратора: ' ITD_ADMIN_PASSWORD
printf '\n'
export ITD_ADMIN_EMAIL ITD_ADMIN_PASSWORD
npm start
```

Администратор создаётся один раз в выбранной базе. Повторный запуск с существующим email не меняет пароль. Email уже зарегистрированного клиента нельзя превратить в администратора этой настройкой. После создания администратора переменные можно убрать и перезапустить сервер: учётная запись сохранится в базе. На общем хостинге используйте защищённые настройки процесса вместо ввода в терминале.

## Работа

1. Клиент открывает «Личный кабинет», выбирает «Регистрация» и создаёт аккаунт. До назначения проекта кабинет пуст.
2. Вы входите под администратором, обновляете список клиентов, создаёте проект и выбираете зарегистрированного клиента по имени и email. Проверяйте email перед назначением документов: подтверждение адреса по почте пока не реализовано.
3. Добавляете этапы, их описания и статусы: «Запланирован», «В работе», «Завершён».
4. Загружаете результаты с привязкой к этапу и документы — подписанный договор, акты и другие готовые файлы. Файлы до 10 МБ: PDF, PNG, JPG, WEBP, TXT, DOCX, XLSX, ZIP.
5. Клиент входит в кабинет и видит только назначенные ему проекты, этапы, результаты и документы. Файлы скачиваются; электронное подписание не предусмотрено. Обновление данных — кнопкой обновления или перезагрузкой страницы.

Администратор может редактировать этапы и удалять материалы. Удаление аккаунтов, переадресация проекта другому клиенту, восстановление пароля по почте и уведомления не входят в эту версию.

## Проверки

```bash
node --test server.test.mjs
node --check server.mjs
node --check cabinet.js
```

Интеграционные тесты используют отдельный временный каталог, создают администратора и клиентов и проверяют регистрацию, назначение проектов, этапы, файлы, запрет чужого доступа, выход, сохранение данных после перезапуска и отсутствие доступа к исходникам/БД по HTTP. Реальные формы Make.com в тестах не отправляются.

## Размещение

Это серверное приложение. Загрузка HTML в Tilda T123 или GitHub Pages сама по себе не запускает кабинет: нужен отдельный Node.js-процесс с постоянным диском. Если публичный сайт остаётся на Tilda, разместите приложение на отдельном домене или поддомене и замените ссылку `/cabinet` на его адрес.

Для публикации настройте HTTPS через доверенный reverse proxy и `ITD_SECURE_COOKIES=1`, задайте `HOST` согласно хостингу, создайте администратора до открытия регистрации. Базу `itd.sqlite` и каталог `files` нужно резервировать вместе при остановленном сервере, а копии хранить с ограниченным доступом. После перезапуска база и документы должны оставаться на том же постоянном диске. Не запускайте несколько экземпляров с независимыми каталогами данных.

Сессия действует сутки. Пароли хранятся как scrypt-хеши, токены сессий — как SHA-256-хеши. Ограничение частоты входа и регистрации действует на IP непосредственного соединения; за reverse proxy пользователи могут разделять лимит. Файлы доступны только после проверки доступа и выдаются как скачиваемые вложения. Их содержимое не проходит антивирусную проверку. Формы публичных страниц по-прежнему используют существующую интеграцию Make.com.
