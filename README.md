# ITD Studio

Сайт студии, кабинет клиента и административная панель. Требуется **Node.js 24.13 или новее в ветке 24 LTS** (используется встроенный `node:sqlite`). Сторонних зависимостей, установки npm-пакетов и сборки нет.

## Локальный запуск

Для начала с нуля откройте `ПЕРВЫЙ-ЗАПУСК.cmd` и введите выбранные вами email и пароль администратора по инструкции [НАЧНИТЕ-ЗДЕСЬ.md](НАЧНИТЕ-ЗДЕСЬ.md). На Windows затем открывайте `ЗАПУСТИТЬ.cmd`, на других системах — `npm start`. Сервер слушает `127.0.0.1:8000`.

- `/` — главная страница;
- `/anketa` — анкета;
- `/cabinet` — регистрация, вход, кабинет и управление для администратора.
- `/reset-password/` — установка нового пароля по одноразовой ссылке администратора.

`PORT` и `HOST` меняют адрес сервера. Путь данных сохраняется один раз в `~/.itd-studio/storage.json` (Windows: `%USERPROFILE%\.itd-studio\storage.json`). Он не зависит от рабочей папки и перезапуска компьютера. `ITD_DATA_DIR` больше не используется. При отсутствии настроек, базы или документов запуск останавливается без создания пустой базы. Первичная настройка создаёт отдельную новую папку `%LOCALAPPDATA%\ITD-Studio\data-…` (macOS/Linux: `~/.local/share/ITD-Studio/data-…`), только первого администратора и проверенную резервную копию. Скрытый ввод пароля доступен в интерактивном терминале: `npm run data:init`. Пароль не принимается аргументом и не сохраняется открытым текстом. Старые данные не ищутся и не открываются; прежний файл настройки сохраняется перед переключением. Повторная инициализация уже настроенной новой базы отклоняется. Подключение существующей базы командой `bind` остаётся доступным отдельно.

## Резервные копии

Остановите все версии приложения. Откройте `РЕЗЕРВНАЯ-КОПИЯ.cmd` или выполните `npm run backup`. Будет создана проверенная папка с датой внутри `ITD-backups`, рядом с выбранной папкой данных. Предыдущие копии сохраняются. Скопируйте всю папку с датой на отдельный внешний диск. Первая копия создаётся автоматически при первоначальной настройке или подключении существующих данных. Проверка и восстановление: [ДАННЫЕ-И-КОПИИ.md](ДАННЫЕ-И-КОПИИ.md).

## Работа

1. Клиент открывает «Личный кабинет», выбирает «Регистрация» и создаёт аккаунт. До назначения проекта кабинет пуст.
2. Вы входите под администратором, обновляете список клиентов, создаёте проект и выбираете зарегистрированного клиента по имени и email. Проверяйте email перед назначением документов: подтверждение адреса по почте пока не реализовано.
3. Добавляете этапы, их описания и статусы: «Не начат», «В работе», «Ожидает согласования», «Нужны изменения», «Согласован», «Завершён».
4. Загружаете результаты с привязкой к этапу и документы — подписанный договор, акты и другие готовые файлы. Файлы до 10 МБ: PDF, PNG, JPG, WEBP, TXT, DOCX, XLSX, ZIP.
5. Клиент входит в кабинет и видит только назначенные ему проекты, этапы, результаты и документы. Файлы скачиваются; электронное подписание не предусмотрено. Обновление данных — кнопкой обновления или перезагрузкой страницы.

Администратор может редактировать этапы и удалять отдельные файлы, которые не включены в историю согласований. Версии согласуемых материалов защищены от удаления. Физическое удаление аккаунтов и проектов, восстановление пароля по почте и внешние уведомления не входят в эту версию. Для завершённых проектов доступен архив.

## Разделы кабинета

Примеры оформления на вымышленных данных: [компьютер](docs/cabinet-preview.png) · [телефон](docs/cabinet-mobile.png).

- **Обзор** администратора — общий рабочий центр: показатели, работа студии, ожидание клиента и ближайшие сроки. Открывается после входа администратора, в том числе без проектов.
- **Обзор проекта** — прогресс по завершённым этапам, текущая работа и краткий план. Для клиента по-прежнему называется «Обзор».
- **Задачи** — внутренние задачи студии с ответственным, необязательным сроком, приоритетом, статусом, поиском и фильтрами. Доступны только администратору.
- **Этапы проекта** — статусы, описания и материалы каждого этапа.
- **Результаты** — файлы работы дизайнера с привязкой к этапам.
- **Документы** — договоры, акты и другие загруженные файлы.
- **Согласования** — версии материалов, решения клиента, комментарии и история. Администратору также доступны отметки просмотров и фильтры.
- **Уведомления** — новые материалы, ответы, решения и первые просмотры внутри кабинета, со счётчиком непрочитанного.
- **Управление** — раздел администратора для создания проектов, добавления этапов и загрузки материалов. Он доступен и до создания первого проекта.
- **Запросы на восстановление** — раздел администратора для проверки клиента, выдачи одноразовой ссылки, отклонения запроса и просмотра истории обработки. Доступен и без проектов.
- **Клиенты** — поиск по имени/email, карточка с проектами, редактирование имени и временное отключение доступа. Email не редактируется.
- **Проекты** — поиск по названию/клиенту, фильтр статуса, карточка управления, архив и подтверждённая смена клиента проекта.

Кабинет запоминает выбранный раздел для каждого проекта до выхода. Счётчики и прогресс вычисляются из данных проекта; календарные сроки и неподтверждённые проценты не придумываются. Обновление данных выполняется кнопкой «Обновить».

## Управление клиентами и проектами

Клиенты регистрируются обычным способом и появляются в разделе «Клиенты». В карточке доступны имя, неизменяемый email, дата регистрации, состояние аккаунта и все назначенные проекты. Поиск работает по имени и email. Отключение требует подтверждения: сеансы клиента завершаются, вход и доступ к файлам блокируются, прежние запросы и ссылки восстановления отзываются. Включение разрешает новый вход, сохраняя проекты и документы; прежние сеансы и ссылки не восстанавливаются. Новый запрос восстановления, оставленный во время отключения, можно одобрить только после включения аккаунта.

В «Проектах» можно искать по названию, имени или email клиента и выбирать фильтр: «Все активные», «Новый», «В работе», «На паузе», «Завершён», «Архив». «Все активные» означает все проекты вне архива, включая завершённые. Кнопка «Создать проект» открывает существующую форму с названием, активным клиентом и первоначальным статусом. В карточке можно изменить название/статус, открыть материалы или передать проект другому активному клиенту. Перед передачей показывается предупреждение и требуется отдельное подтверждение; сервер проверяет, что назначение не изменилось с момента открытия карточки. Файлы не копируются, доступ определяется текущим клиентом проекта.

Архив — только статус: этапы, документы, изображения, связь с клиентом и история остаются на месте. Архивные проекты скрыты из основного списка; их можно найти фильтром «Архив», а в боковом списке кабинета — включить отображение архивных проектов. Клиент сохраняет доступ к своим архивным материалам. Восстановление возвращает прежний статус. Прогресс — доля завершённых этапов; у проекта без этапов процент не выдумывается.

При запуске автоматически добавляются поля даты регистрации/создания, активности клиента и предыдущего статуса проекта, а также таблица административных событий. Прежние значения сохраняются, неизвестные исторические даты отображаются как «Не указана». История карточки клиента объединяет новые административные действия с существующим журналом восстановления пароля. Новые поля и журнал входят в обычную резервную копию SQLite без изменения механизма копирования. Пошаговая инструкция: [КЛИЕНТЫ-И-ПРОЕКТЫ.md](КЛИЕНТЫ-И-ПРОЕКТЫ.md).

## Рабочий центр, задачи и сроки

Общий обзор считает реальную работу по проектам вне статусов «Завершён» и «Архив». Запросы изменений и обсуждения без ответа студии отделены от материалов, по которым ожидается решение клиента. Прочтение уведомления или открытие карточки не закрывает работу. Неотвеченные сообщения учитываются отдельно по каждой версии; новая версия не подменяет ответ на старое сообщение.

Задачи относятся к проекту и, при необходимости, этапу. Ответственные выбираются только из существующих активных администраторов. Статусы: «К выполнению», «В работе», «Выполнено», «Отменено». Даты этапов и сроки задач необязательны. Сравнение сроков использует календарную дату в часовом поясе браузера; просрочка не меняет основной статус этапа. Завершённые и отменённые задачи, завершённые этапы и неактивные проекты не создают ложных просрочек.

При запуске добавляются таблица `admin_tasks` и пустые поля `startDate`, `plannedEndDate` у прежних этапов. Существующие значения и файлы сохраняются. Новые данные включаются в обычную резервную копию. Архивирование не меняет статусы задач и не удаляет их. Изменения задач и сроков записываются в прежний журнал. Инструкция по работе и безопасному обновлению: [РАБОЧИЙ-ЦЕНТР.md](РАБОЧИЙ-ЦЕНТР.md).

## Согласования и просмотры

Результат работы можно отправить на согласование при загрузке в этап или отдельно включить прежний файл результата. Новая версия сохраняет старый файл и историю; решения и просмотры не переносятся на неё. Клиент подтверждает согласование либо отправляет обязательный комментарий с запросом изменений. Администратор отвечает, загружает новый вариант или отменяет согласование с обязательной причиной и подтверждением.

Просмотр учитывается только после успешного показа изображения или страницы PDF во встроенном просмотрщике клиента. Миниатюры, списки, открытие карточки, скачивание и просмотр администратором не отмечают материал просмотренным. Первый и последний просмотр хранятся отдельно для каждой пары «версия + клиент». Первое открытие создаёт событие и уведомление администратору; повторные обновляют только последний просмотр и счётчик. Это сигнал открытия, а не доказательство внимательного ознакомления.

Новые таблицы `review_materials`, `review_versions`, `review_events`, `review_notifications`, `review_views` добавляются при запуске. Существующие файлы не включаются в согласование автоматически. История событий не перезаписывается; операции проверяют текущего клиента проекта и актуальность версии. Архив и обычная резервная копия сохраняют новые данные. Подробная инструкция: [СОГЛАСОВАНИЯ.md](СОГЛАСОВАНИЯ.md).

## Восстановление пароля через администратора

Клиент нажимает «Забыли пароль?» на странице входа и вводит email. Для существующего и несуществующего аккаунта ответ одинаков: «Если такой аккаунт существует, запрос отправлен администратору». Письма и сообщения автоматически не отправляются.

Администратор открывает «Запросы на восстановление», проверяет личность клиента по уже известному контакту и нажимает «Разрешить сброс». После подтверждения копирует ссылку кнопкой «Скопировать ссылку» и сам отправляет клиенту. Срок ссылки — **20 минут с момента её создания**. После обновления страницы готовая ссылка недоступна: можно создать новую, а прежняя станет недействительной. Администратор никогда не видит новый пароль.

Клиент открывает ссылку, дважды вводит новый пароль длиной 12–256 символов и затем входит обычным способом. Старый пароль и все прежние сеансы этого клиента перестают работать; использованная ссылка повторно не действует. После истечения срока клиент может оставить новый запрос. Подробная инструкция: [ВОССТАНОВЛЕНИЕ-ПАРОЛЯ.md](ВОССТАНОВЛЕНИЕ-ПАРОЛЯ.md).

Восстановление предназначено для аккаунтов клиентов. Запрос неизвестного email виден администратору, но одобрить его нельзя. Если аккаунт зарегистрирован позже запроса, сначала отклоните прежний запрос и попросите клиента отправить новый.

При запуске автоматически добавляются отдельные таблицы запросов, событий и ограничений частоты; существующие аккаунты и проекты не пересоздаются. Криптографически случайный код состоит из 32 байтов; в базе хранится только SHA-256-хеш. Сам код находится после `#` в ссылке, поэтому не передаётся в адресе HTTP-запроса. Страница извлекает его в память и сразу убирает из адресной строки. Ни код, ни пароль не записываются приложением в журнал. Журнал сохраняет даты, действия и исполнителей; резервная копия SQLite включает новые таблицы автоматически.

Защита от спама: до 5 запросов восстановления и до 20 попыток установки пароля за 15 минут с IP непосредственного соединения. Повторные обращения по одному email не создают десятки открытых запросов и не отменяют уже выданную ссылку. Ограничения сохраняются после перезапуска. За reverse proxy клиенты могут разделять один лимит; заголовкам с произвольным IP приложение не доверяет.

## Проверки

```bash
npm test
node --check server.mjs
node --check cabinet.js
```

Интеграционные тесты используют отдельный временный каталог, создают администратора и клиентов и проверяют регистрацию, назначение проектов, этапы, файлы, запрет чужого доступа, выход, сохранение данных после перезапуска и отсутствие доступа к исходникам/БД по HTTP. Дополнительно проверяются постоянный путь, реальные перезапуски и аварийное завершение процесса, копирование, восстановление и отказ от повреждённых данных. Тесты не отправляют заявки во внешние сервисы.

`password-recovery.test.mjs` проверяет восстановление, ограничения доступа, одноразовость, истечение срока, аннулирование сессий и сохранение данных. `tests/browser-recovery.mjs` проверяет формы клиента и администратора в настоящем браузере; запуск с тем же Playwright, что и проверка галереи:


`admin-management.test.mjs` проверяет управление, права, блокировку аккаунтов, передачу проекта, архив, обновление прежней базы и сохранность копий. `tests/browser-admin.mjs` проверяет карточки, формы, подтверждения, поиск и фильтры на ширинах 1440/768/430/375:


`material-review.test.mjs` проверяет согласования, версии, комментарии, просмотры, уведомления, права, архив, перезапуск и восстановление резервной копии. `tests/browser-review.mjs` проверяет полный сценарий в браузере на ширинах 1440/768/430/375, включая отличие реального открытия изображения/PDF от загрузки миниатюр:


`admin-workspace.test.mjs` проверяет рабочие очереди, задачи, сроки, календарные границы и часовые пояса, права, архив, обновление прежней базы, перезапуск и копии. `tests/browser-workspace.mjs` проверяет общий обзор, формы, фильтры и переходы на ширинах 1440/768/430/375:

## Размещение

Это серверное приложение. Загрузка HTML в Tilda T123 или GitHub Pages сама по себе не запускает кабинет: нужен отдельный Node.js-процесс с постоянным диском. Если публичный сайт остаётся на Tilda, разместите приложение на отдельном домене или поддомене и замените ссылку `/cabinet` на его адрес.

Для публикации настройте HTTPS через доверенный reverse proxy и `ITD_SECURE_COOKIES=1`, задайте `HOST` согласно хостингу, подключите существующую базу с администратором до открытия регистрации. Базу `itd.sqlite` и каталог `files` нужно резервировать вместе при остановленном сервере, а копии хранить с ограниченным доступом. После перезапуска база и документы должны оставаться на том же постоянном диске. Не запускайте несколько экземпляров с независимыми каталогами данных.

Сессия действует сутки. Пароли хранятся как scrypt-хеши, токены сессий — как SHA-256-хеши. Ограничение частоты входа и регистрации действует на IP непосредственного соединения; за reverse proxy пользователи могут разделять лимит. Файлы доступны только после проверки доступа и выдаются как скачиваемые вложения. Их содержимое не проходит антивирусную проверку. Отправка заявки и анкеты на публичных страницах отключена: интеграция с Make.com удалена. На страницах показано уведомление и ссылка для связи со студией в Telegram. Данные форм никуда не отправляются.

## Просмотр материалов в кабинете

В «Результатах» JPG/JPEG, PNG и WebP показаны галереей по этапам. Нажмите миниатюру для крупного просмотра; доступны предыдущий/следующий файл, увеличение, сброс масштаба, закрытие и скачивание оригинала. На телефоне изображения можно листать свайпом при обычном масштабе; увеличенное изображение прокручивается. Миниатюры загружаются по мере появления на экране, оригиналы на диске не изменяются.

Названия в карточках занимают одну строку; длинные обрезаются многоточием, полное имя видно при наведении мыши. При открытии изображение вписывается в свободную ширину и высоту окна с сохранением пропорций. 100% означает размер, вписанный в окно (маленькие оригиналы не растягиваются). Выбранный масштаб запоминается отдельно для каждой картинки до закрытия просмотрщика. Переключение не перезагружает страницу; после закрытия сохраняется место в галерее.

У PDF есть кнопка открытия: страницы отображаются внутри кабинета, с перелистыванием, масштабом и скачиванием. PDF.js 6.4.299 и его шрифты/worker/декодеры включены в `vendor/pdfjs/`; установка npm-пакетов при запуске не нужна. Нет CDN или внешнего сервиса просмотра. Выполняется только отрисовка страниц: активные сценарии PDF, интерактивные формы, вложения и ссылки не исполняются. Повреждённые или защищённые паролем PDF могут быть недоступны для просмотра; оригинал можно скачать.

DOCX, XLSX, ZIP и TXT остаются доступными для скачивания. Просмотр, как и скачивание, требует входа и доступа к проекту. Прямая ссылка не открывает чужой файл. При выходе/смене проекта просмотр закрывается, временные адреса и незавершённые загрузки очищаются. Оригиналы файлов, регистрация, вход, запуск и порядок резервного копирования не меняются; просмотры согласуемых версий учитываются, как описано выше.

### Обновление уже работающего приложения

1. Остановите приложение через Ctrl+C. При желании создайте копию обычным `РЕЗЕРВНАЯ-КОПИЯ.cmd`.
2. Распакуйте новую версию целиком в отдельную папку, включая `vendor`. Старую папку и данные не удаляйте.
3. Откройте **ЗАПУСТИТЬ.cmd** из новой папки: сохранённый адрес данных используется автоматически. **ПЕРВЫЙ-ЗАПУСК.cmd и повторное подключение данных не нужны.**
4. В браузере обновите кабинет через Ctrl+F5. Проверьте изображение и PDF в своём проекте.

### Дополнительные проверки просмотра

`npm test` включает авторизацию preview, отказ прямых ссылок чужому клиенту, оригинальные байты файлов после перезапуска и проверку контрольных сумм локального PDF.js. `tests/browser-preview.mjs` — отдельная браузерная проверка с Playwright и Chromium: короткие и длинные названия, равная высота карточек, вертикальные/широкие/большие изображения, вписывание в окно, сохранение масштаба по изображениям, настоящая отрисовка двух страниц PDF, скачивание, выход, отсутствие сторонних сетевых запросов и экраны 1440/430/390/375/320 пикселей. Использует только временные тестовые данные.

Для разработчика, если Playwright установлен вне проекта:

```sh
ITD_PLAYWRIGHT_MODULE=file:///tmp/itd-browser/node_modules/playwright/index.mjs node tests/browser-preview.mjs
```

По умолчанию Chromium берётся из `/usr/bin/chromium`; другой путь задаётся через `ITD_CHROMIUM`. Для самого приложения эти инструменты не нужны.
