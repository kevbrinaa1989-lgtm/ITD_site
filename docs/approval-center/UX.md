# UX-решения и оценка дополнительных идей

Прежний процесс заставлял открывать версии и принимать решения по одному файлу, без общей проверяемой сводки, устойчивого черновика и привязки замечаний к точке на листе. В просмотре не было достаточного различия между «открыл», «проверил», «дизайнер исправил» и «клиент принял». Автоматическое принятие этапа после последнего файла смешивало два разных решения.

В новом сценарии клиент сначала проверяет материал, готовит решения и замечания, затем видит сводку и отправляет пакет. Это уменьшает риск случайной окончательной отправки. На телефоне у списка, просмотра и решений отдельные панели; кнопки имеют доступные подписи, клавиатурный фокус и достаточный размер. Состояние черновика видно рядом с отправкой. Дизайнер работает с очередью и отчётом исправлений; администратор выбирает проекты в существующем кабинете, не получает второй независимый список проектов.

## Оценка идей

| Идея | Польза и удобство | Сложность | Риск ошибочного согласования | Производительность | Решение |
|---|---|---|---|---|---|
| Сетка/список | Быстро узнавать визуализации и читать длинные имена | Низкая | Низкий: выбор не является решением | Ленивые миниатюры | Реализовано |
| Помещения | Упорядочивает 50+ файлов | Средняя: нужны реальные поля | Не выводим помещение из имени файла | Сортировка метаданных | Реализовано |
| Только новые версии | Экономит время повторной проверки | Низкая | Низкий, старые решения не переносятся | Не загружает старые оригиналы | Реализовано |
| Стрелки клавиатуры | Ускоряют просмотр на компьютере | Низкая | Не работают как команды согласования | Один активный просмотр | Реализовано |
| Возврат к последнему месту | Помогает продолжить с телефона/после перерыва | Средняя | Состояние связано с точной версией | Небольшой серверный черновик | Реализовано |
| Сводка незавершённого | Видны подготовленные решения и препятствия этапа | Средняя | Снижает риск неполной отправки | Счётчики по загруженным метаданным | Реализовано |
| Отдельная история замечания | Понятны автор, дата и причины изменения | Средняя | Исходное замечание неизменяемо | Текст, без загрузки всех оригиналов | Реализовано |
| Большие PDF | Проверка всех страниц, масштаб, освобождение canvas | Средняя | Число страниц проверяет сервер | Один активный лист на просмотр, ограниченный canvas | Реализовано |
| Ускоренная повторная проверка | Сравнение, отчёт, фильтр исправлений | Высокая | Подтверждение замечания не принимает файл | Два оригинала только в сравнении | Реализовано |
| Следующее открытое замечание | Меньше ручных переходов при большой очереди | Низкая | Не должно автоматически закрывать замечания | Только смена выбранного элемента | Высокоприоритетное дополнение; сейчас есть фильтр очереди и переход к маркеру |
| Групповой комментарий | Полезен для одинаковых правок в серии | Средняя | Высокий риск неверного назначения всем | Нужен предпросмотр адресатов | Перспективно; не заменяет обязательные комментарии каждого материала |
| Сравнение произвольных раундов | Полезно для анализа долгого проекта | Высокая | Нужно явно показывать выбранные версии | Ограничивать число параллельных оригиналов | Перспективно; сейчас соседние версии и неизменяемая история всех раундов |
| Краткая памятка перед первым пакетом | Снижает растерянность клиента | Низкая | Может объяснить разницу файла и этапа | Незначительно | Высокоприоритетное дополнение после наблюдения за реальными клиентами |

Обязательные функции ТЗ реализованы независимо от этих дополнительных предложений. Физическая мобильная приёмка остаётся открытым условием выпуска, а не будущей необязательной функцией.
