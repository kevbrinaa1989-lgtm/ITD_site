## Воспроизведение

Node.js 24.13–24.x; `npm ci`, затем `npm test`. Playwright установлен отдельно от производственных зависимостей. `ITD_PLAYWRIGHT_MODULE` может указывать на его `index.mjs`; `ITD_CHROMIUM` — на установленный Chrome/Edge/Chromium.

```sh
ITD_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs ITD_CHROMIUM=/path/to/chrome node tests/browser-approval-center.mjs
ITD_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs ITD_CHROMIUM=/path/to/chrome node tests/browser-approval-pdf.mjs
ITD_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs ITD_BROWSER=webkit ITD_NO_SCREENSHOTS=1 node tests/browser-approval-center.mjs
```

`ITD_SCREENSHOT_DIR` задаёт папку снимков; `ITD_BROWSER_IMAGE` — необязательную локальную PNG-иллюстрацию (по умолчанию используются существующие тестовые пиксели из репозитория); `ITD_MATERIAL_COUNT=100` включает браузерную проверку большого комплекта. Установленные браузеры и библиотеки машины не включены в PR.

## Проверка на телефоне

Подключите телефон к той же сети Wi-Fi, что и компьютер с запущенной демоверсией. Откройте адрес кабинета из окна запуска или из сообщения о приёмке. Там же доступны данные для входа и ссылка на трёхстраничный файл для дизайнера. Адрес работает, пока включён компьютер и запущен стенд. Телефону нужен доступ к компьютеру внутри сети по TCP на порт 4175. Гостевая сеть с изоляцией устройств такой доступ блокирует.

| Браузер на устройстве | Этап в проекте «Балтика» | Приёмка |
|---|---|---|
| Samsung Internet на Android | Планировочное решение | Ожидает устройства |
| Chrome на Android | Концепция | Ожидает устройства |
| Safari на iPhone или iPad | Визуализации | Ожидает устройства |

1. Войдите как клиент. Откройте «Мои проекты» → «Балтика» → «Согласования» и выберите этап из таблицы. В нём два PDF. Для полного цикла с 40 файлами есть отдельный этап «Обмеры».
2. Откройте «01-Общий-план». Проверьте переключение между тремя панелями, масштаб двумя пальцами и листание между материалами. В панели «Замечания и решение» подтвердите просмотр и нажмите «Согласовать».
3. Откройте «02-Перегородка». После первого листа попробуйте подтвердить просмотр. Ожидается сообщение «Просмотрены 1 из 2 страниц». На втором листе добавьте маркер и текст, в панели решения напишите пояснение и нажмите «На доработку». Нажмите «Сохранить сейчас». Перезагрузите страницу и снова выберите тот же этап. Должны сохраниться маркер на листе 2 и сводка с одним согласованием и одним возвратом.
4. Нажмите «Проверить и отправить» и подтвердите пакет. В «История и ведомости» откройте ведомость первого раунда и скачайте PDF. В другом окне браузера войдите как дизайнер, откройте тот же проект и этап. Скачайте образец «Перегородка-v2.pdf» по ссылке из окна запуска. Для возвращённого файла нажмите «Загрузить исправленную версию», приложите образец и заполните описание, отметку и пояснение по замечанию.
5. Вернитесь к клиенту и нажмите «Обновить данные». Откройте текущую версию «Перегородки» и «Было / Стало». Слева два листа, справа три. Старый маркер виден только на втором листе v1. Подтвердите исправление с пояснением. Просмотрите три листа v2, подтвердите просмотр, согласуйте файл и отправьте второй пакет. Проверьте вторую ведомость, затем отдельно нажмите «Готовность этапа» → «Подтверждаю согласование этапа».

Для каждого из трёх браузеров запишите модель устройства, версии ОС и браузера и результат шагов 1–5. При сбое укажите последний шаг и приложите снимок с сообщением. Если доступна удалённая консоль устройства, сохраните относящиеся к этому шагу ошибки и статусы запросов без данных входа. Во время подготовки стенда вход, панели и PDF проверены с компьютера по адресу Wi-Fi. Физические устройства и подключённый сервис с ними в этой сессии были недоступны.
