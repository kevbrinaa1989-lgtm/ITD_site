# Данные и восстановление

Приложение использует одну подключённую папку, даже если новая версия кода распакована в другом месте. В ней: `itd.sqlite` (аккаунты, проекты, этапы, сведения о документах), `files` (сами документы), `.itd-operation.sqlite` (защита от одновременного запуска). Папку нельзя удалять, переносить или переименовывать без перенастройки. В текущем обновлении переноса нет.

Адрес сохраняется в `.itd-studio/storage.json` домашней папки пользователя системы. В Windows: `%USERPROFILE%\.itd-studio\storage.json`. Запуск из другой рабочей папки или новой версии этот адрес не меняет. Если сменить пользователя Windows, приложение попросит подключить данные и ничего не создаст автоматически.

## Восстановление на новом компьютере — Windows

1. Установите Node.js 24 LTS (не ниже 24.13). Скачайте и распакуйте приложение в новую папку.
2. Подключите внешний диск. Найдите папку копии с датой, содержащую `itd.sqlite`, `files`, `backup.json`. Сохраните исходную копию на внешнем диске.
3. В папке приложения, где лежит `server.mjs`, нажмите адресную строку Проводника, введите **cmd**, нажмите Enter. Откроется окно команд.
4. Введите команду ниже, заменив `E:\ITD-копия` полным адресом вашей папки копии. Кавычки оставьте, нажмите Enter:

   ```bat
   node storage-cli.mjs verify "E:\ITD-копия"
   ```

   Дождитесь «Копия проверена», проверьте число аккаунтов и проектов. При ошибке остановитесь: попробуйте другую копию или сообщите текст ошибки помощнику.

5. В Проводнике откройте «Документы», создайте папку **ITD-восстановление**, откройте её и скопируйте полный адрес. Введите следующую команду, заменив оба примера вашими адресами:

   ```bat
   node storage-cli.mjs restore "E:\ITD-копия" "C:\Users\ВашеИмя\Documents\ITD-восстановление\.itd-data"
   ```

   Папка `.itd-data` в конце второго адреса **ещё не должна существовать**. Программа создаёт только новую папку, отказывается заменять существующую. Дождитесь «Копия восстановлена в новую папку». Если восстановление прервалось, выберите для следующей попытки другое новое имя папки.

6. Откройте **ПОДКЛЮЧИТЬ-ДАННЫЕ.cmd**, укажите адрес восстановленной `.itd-data`, проверьте числа и введите **ДА**. Будет создана проверенная копия и сохранён адрес.
7. Откройте **ЗАПУСТИТЬ.cmd**, войдите в кабинет прежним аккаунтом. Проверьте проект и скачайте документ. Пароли остаются прежними.

Если на компьютере **уже подключена другая папка**, восстановление подготовит новую, но не переключит приложение автоматически. Прежние данные и настройки не удаляйте. Сообщите помощнику путь восстановленной папки для отдельного безопасного переключения.

## Команды для разработчика и macOS/Linux

Из папки кода, с абсолютными адресами в кавычках:

```sh
node storage-cli.mjs bind "/полный/путь/.itd-data"
node storage-cli.mjs status
npm start
# После остановки всех версий сервера:
npm run backup
node storage-cli.mjs backup "/внешний/диск/ITD-backups"
node storage-cli.mjs verify "/путь/к/копии-с-датой"
node storage-cli.mjs restore "/путь/к/копии-с-датой" "/существующий/родитель/новая-папка"
```

`bind` без аргумента спрашивает адрес и подтверждение. С явным адресом подтверждение подразумевается командой. Подключение проверяет существующую базу и документы, создаёт первую копию. При отказе настройки не меняет. Повторное подключение того же адреса сохраняет настройку, другой адрес отвергается. `ITD_DATA_DIR` игнорируется. Создание пустой рабочей базы намеренно не встроено в обычный запуск. `createApp({dataDir})` оставлен только для изолированных тестовых данных разработчика.

Копирование использует SQLite Backup API, включая зафиксированные изменения WAL-журнала, переносит все обычные файлы из `files`, проверяет базу, ссылки на документы, размеры и контрольные суммы. `backup.json` появляется в конце. Символические ссылки внутри документов не допускаются. Новые версии приложения и копирование блокируют одновременную работу с папкой. **Старые версии блокировку не знают: обязательно остановите их вручную.** Используйте локальный постоянный диск, не сетевую папку с неизвестными гарантиями блокировки.

Копии не шифруются приложением. Автоматической очистки и расписания нет. Храните внешний диск в безопасном месте; при необходимости используйте шифрование диска средствами системы. Проверка целостности обнаруживает повреждение, но не заменяет защиту от постороннего доступа.

`npm test` создаёт и удаляет только отдельные временные данные. Настоящие базы не используются.
